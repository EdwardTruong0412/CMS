3. Error and log exposure: the 503 path logs only the exception class (`src/api/app/services/system.py:18`). The unhandled-error handler logs only method and path, without the query string, body or headers, and returns a generic `INTERNAL_ERROR`. Validation errors leave out pydantic's `input`, so request values are not echoed back. One thing for later: `ctx` values pass through `str()` (`src/api/app/errors.py:47`). A future custom `field_validator` that puts user input into its error message would then echo that input in `params`. Later stories should keep validator messages free of input values.

That does no harm now, because no route takes query parameters. Once the employee search or list stories add query parameters such as names or e-mails, start uvicorn with `--no-access-log` or use a path-only access log. Also think about `--no-server-header`.
